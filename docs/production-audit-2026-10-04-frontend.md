## Authentication, authorization, tenancy and APIs

The browser receives a revocable opaque session cookie, not the shared backend API credential. It is HttpOnly, SameSite=Lax, path `/`, Secure in production and bounded to 12 hours. Server pages revalidate it through `auth/me`, with password-change, onboarding, product-tour and admin gates. Logout/password changes use backend session revocation; cookie deletion uses the same security attributes. Login/setup/password routes are same-origin mutations, byte bounded and return safe fallback errors. Password setup uses a fragment token and clears the fragment immediately, reducing referral/log exposure. There is no public signup, general email-verification or social login in the dashboard; employee invitation/setup and MCP consent are the implemented flows.

The same-origin proxy uses an explicit method/path allowlist and authenticated cookie. It forwards the shared API credential and session only server-side, disables fetch caching and refuses upstream redirects. Client origin checks are defense in depth; backend actor/resource ownership remains the actual authorization boundary. Browser actor/context IDs are not treated as authoritative by this frontend. Workspace and Chat reference the same canonical records rather than separate stores. API pagination and context validation are handled through the existing backend contract, with bounded UI selections and request bodies. Every frontend entry point was checked for this delegation. Frontend mocked tests alone do not prove tenant isolation; the parent additionally reported successful real HTTP cross-account isolation/revocation checks against a disposable production-configured database.

MCP return navigation is constrained to its validated local consent path. External provider callback/state/grant validation belongs to the backend audit. Ordinary links validate schemes, reject credential-bearing/protocol-relative URLs where appropriate and use safe external navigation. Model prose is rendered with raw HTML disabled, remote Markdown images removed and constrained links; user/provider text is escaped by React. The only direct HTML insertion is a constant theme bootstrap with the request nonce. No SQL/command execution, user file path, arbitrary server fetch target, object merge/deserialization or runtime `eval` exists in the frontend reviewed. CSV import is parsed and schema-limited before the server validates each record. The SQLite export is an authenticated confirmation/download, not public storage.

Same-origin browser routing does not add unrestricted CORS. No frontend environment variable is prefixed `NEXT_PUBLIC_`; API token and provider secrets stay in server modules/backend storage. Secret controls reveal only the user's current replacement input, never a stored key. Logs contain no added session/password/provider values; dashboard source has no production `console.log` or `debugger` statements. Browser local storage contains theme/tour progress, with tour state keyed by account; workspace cross-tab notifications carry invalidation metadata, not customer records or credentials. Authenticated HTML and API responses are uncached. Static brand/fonts are public intentionally.

The parent clean install and production build passed. Chat reconnects sequentially and aborts/cancels readers on unmount; SSE parses chunked UTF-8 and CRLF framing with a bounded buffer. Stored-data hooks abort stale reads and guard overlapping polls. Lead-detail now guards overlap too. Async forms retain edits after errors, block duplicate submissions, preserve request IDs across uncertain retries and show actual backend status. Paid lookup, mailbox access, sending and standing Autopilot scope all require explicit UI confirmation; actual external authorization/idempotency is verified in the backend/worker reports. No chargeable action was tested here. Lists have bounded pagination or limited rendered views; no frontend production load benchmark was run.

- **MEDIUM:** Full browser/CSP/mobile/accessibility checks above are UNVERIFIED and must run on the final build with trusted HTTPS before real users.
- **MEDIUM:** Hosting/ingress request size and request duration limits must be configured. Route bodies are bounded, but Next's routing proxy can clone/buffer requests before handlers; an ingress body limit remains necessary against high-volume abuse. The selected platform must support the 80-second route budget for the longest operation or that path must use supported asynchronous behavior. No unrestricted application refactor was attempted.
- **LOW:** The default 24-worker test run on this workstation had four timing-related failures, including 5-second timeouts and a pending input event affecting the next test. CPU contention is an inference from the high-concurrency run and successful bounded reruns, not a separately measured root cause. The complete unchanged suite passed with two workers, both before and after final fixes. No assertions/timeouts were weakened. CI should use bounded workers on its available CPU budget.
- **UNVERIFIED:** Production provider credentials/domains, actual invitation delivery, real mailbox lookup/sending, paid discovery, production data volumes and hosting-plan limits. These need operator-specific verification; no paid/send permission was inferred.
